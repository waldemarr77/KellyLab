# Як розібрати KellyLab завтра

## 1. Спочатку запусти сценарій (15 хв)

Запусти сервер за README, потім `examples/demo.ps1`. Подивись JSON карток і TXT-файл. Після цього відкрий Swagger та вручну створи ще одну сесію. Мета — бачити, яку дію користувача обслуговує код.

## 2. Шлях одного запиту (25 хв)

Почни з `config/urls.py`: router пов'язує URL із методом viewset. `SessionViewSet` у `sessions/views.py` дістає тільки сесії `request.user`. `SessionSerializer` у `sessions/serializers.py` перевіряє назву та не дає клієнту встановити статус або ID задачі. `perform_create()` прив'язує запис до користувача з токена. Модель у `sessions/models.py` описує таблицю.

Поясни вголос: чому переданий клієнтом `user=123` не повинен визначати власника? Чому одного `IsAuthenticated` недостатньо? Що станеться, якщо забрати фільтр із `get_queryset()`?

## 3. Реєстрація та JWT (20 хв)

Читай `users/serializers.py` і `users/views.py`. Пароль перевіряють Django validators, а `create_user()` зберігає його хеш. `write_only` приховує пароль у відповіді. Email є логіном, технічний username генерується автоматично. JWT перевіряє користувача; фільтрація queryset визначає, які дані він може бачити.

Питання: чим access відрізняється від refresh? Чому не можна робити `CustomUser.objects.create(password=...)`? Чому хешування — не шифрування? Як можна відкликати вже виданий JWT і чого тут поки немає?

## 4. Імпорт і транзакції (25 хв)

`ImportSerializer` приймає рівно одне джерело, перевіряє розмір, UTF-8 і кількість питань. `import_questions()` перевіряє сесію під блокуванням і створює картки через `bulk_create`. `transaction.atomic()` об'єднує зміни. `select_for_update()` серіалізує конкурентні операції з однією сесією на PostgreSQL; у SQLite аналогічної гарантії рядкового блокування немає.

Питання: що буде, якщо два запити одночасно імпортують питання? Чим перевірка в Python відрізняється від обмеження в БД? Яких перевірок не виконує `bulk_create()` порівняно зі звичайним `save()`?

## 5. Celery та AI (30 хв)

`generate()` спочатку записує `processing` і унікальний ID запуску, завершує транзакцію, потім публікує задачу. Redis є брокером, Celery worker виконує `questions/tasks.py`. `questions/ai.py` ізолює зовнішній сервіс від решти коду.

Мережеві запити виконуються поза транзакцією, щоб не утримувати блокування БД, поки AI відповідає. Готові відповіді зберігаються разом у короткій транзакції. ID запуску захищає від запису результатів старої задачі після нового запуску. Це не гарантує «рівно один виклик AI»: повторна доставка може призвести до зайвих викликів, хоча застарілі результати не перезапишуть новий стан.

Питання: чому не викликати AI прямо у view? Чому задача має побачити вже закомічені дані? Що станеться, якщо Redis недоступний? Якщо процес впаде між commit і publish? Як transactional outbox або періодичне відновлення допоможуть у наступній версії?

## 6. Правки й тести (20 хв)

У картки є `ai_answer` та `user_answer`. Відображуване `answer` обирається серіалізатором. `None` і порожній рядок мають різний зміст. При редагуванні тексту AI-відповідь скидається; особисті нотатки залишаються. Експорт використовує ту саму перевагу власної відповіді.

Прочитай `sessions/test_api.py` та `users/test_api.py`: почни з повного сценарію, потім із тесту чужого користувача. `patch()` заміняє зовнішній виклик, щоб детерміновано перевірити помилку без мережі та витрат.

## Самостійна зміна (20–30 хв)

Додай пошук сесій за назвою через `?search=django`. Перевір, що пошук не повертає сесії іншого користувача, і напиши один тест саме на це. Це невелика зміна, яка проходить через API, queryset та перевірку доступу.

## Як описувати проєкт на співбесіді

«KellyLab — API підготовки до співбесід. Користувач імпортує питання, запускає генерацію, редагує відповіді й експортує матеріал. Django/DRF обслуговує API, PostgreSQL зберігає дані, Celery і Redis відокремлюють повільну генерацію від HTTP. Зовнішній AI винесений в окремий модуль. Я використав AI-помічника для написання коду й розібрав реалізацію та її обмеження».

Останню частину кажи після власного розбору. Будь готовий показати конкретний метод, тест і свою зміну. У деморежимі немає справжньої AI-генерації; у цій версії немає React, PDF/DOCX, автоматичної перевірки коду або LangGraph workflow.
